Getting started with biocUniTools

biocUniTools is a package for working with Bioconductor build data in R Universe. In this vignette, we’ll get build results from the Bioconductor Build System (BBS) and R Universe for comparison.

library(biocUniTools)

Bioconductor branches and package types

uni_for_bioc() gives the Bioconductor version, R version, and universe for a branch.

bu <- uni_for_bioc("devel")
bu
$bioc_version
[1] "3.24"

$bioc_branch
[1] "devel"

$universe
[1] "bioc"

$r_version
[1] "4.6.0"

bioc_manifest() lists the packages of a type in a branch.

experiments <- bioc_manifest("devel", "data-experiment")
head(experiments)
[1] "affydata"                "AffymetrixDataTestFiles"
[3] "ALL"                     "ALLMLL"                 
[5] "AmpAffyExample"          "beta7"

BBS results

bbs_nodes() lists the BBS build machines for a type.

bbs_nodes("devel", "data-experiment")
       node                         os   arch         platform
1 nebbiolo2 Linux (Ubuntu 24.04.4 LTS) x86_64 x86_64-linux-gnu
                          r_version
1 4.6.1 (2026-06-24) -- "Happy Hop"

bbs_status() returns one row per package from one build machine. By default, it shows the builder for Linux x86_64. It has the version and commit the BBS built plus the result of each stage.

bbs <- bbs_status("devel", "data-experiment")

R Universe results

uni_jobs() downloads R Universe data for a branch. It can download jobs for all packages in a universe or a vector of packages.

jobs <- uni_jobs("devel", packages = experiments)

uni_status() returns one row per package type.

Note: source_build is the result of R CMD build on the source package to build vignettes in R Universe. check is the result of R CMD check of the Linux x86_64 binary job.

uni <- uni_status("devel", "data-experiment", jobs = jobs)
head(uni[, c("Package", "Version", "commit", "status", "source_build", "check",
             "bioccheck")])
           Package Version  commit  status source_build   check bioccheck
1              ALL  1.55.0 c705298 success           OK    NOTE     ERROR
2           ALLMLL  1.53.0 c02b4ee success           OK    NOTE     ERROR
3         ARRmData  1.49.0 359b678 success           OK    NOTE     ERROR
4        ASICSdata  1.33.0 a4b6bb4 success           OK WARNING     ERROR
5 AWAggregatorData   1.3.0 1ef37b1 success           OK      OK      NOTE

Comparing results between the BBS and R Universe

compare_builds() joins both results by package. It adds whether both systems built the same commit and whether they have the same result. Results are compared after normalize_result(), which treats NOTE as OK and WARNING(S) the same.

normalize_result(c("OK", "NOTE", "WARNINGS", "WARNING", "ERROR"))
[1] "OK"      "OK"      "WARNING" "WARNING" "ERROR"  
cmp <- compare_builds("devel", "data-experiment", bbs = bbs, uni = uni)
head(cmp[, c("Package", "where", "commit_match", "bbs_result", "uni_result",
             "result_match")])
           Package where commit_match bbs_result uni_result result_match
1              ALL  both         TRUE         NA       NOTE        FALSE
2           ALLMLL  both         TRUE         NA       NOTE        FALSE
3         ARRmData  both         TRUE         NA       NOTE        FALSE
4        ASICSdata  both         TRUE         NA    WARNING        FALSE
5 AWAggregatorData  both         TRUE         NA         OK        FALSE
6 Affyhgu133A2Expr  both         TRUE         NA         OK        FALSE

For workflows, the BBS does not run R CMD check, so compare_builds() compares R CMD build.

compare_summary() counts the matches and differences.

compare_summary(cmp)
  branch            type packages both bbs_only universe_only commits_match
1  devel data-experiment      440  420       19             1           419
  commits_differ results_match results_differ check_diverged
1              1             0            420              1

Reports

The BBS and R Universe report pages on the biocUniTools website are made from this data. Their source is on the reports branch of the biocUniTools repository. write_comparisons() saves a comparison for every branch and type listed in a YAML configuration, and the report pages read the saved files:

write_comparisons("reports/config.yml")

compare_table(), compare_header(), compare_bars(), and compare_details() make the parts of each page, so you can use them in your own reports.
